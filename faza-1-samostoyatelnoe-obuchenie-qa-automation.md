# Фаза 1. Самостоятельное обучение: путь в QA Automation на Python

Этот файл — твой план на ближайшие несколько месяцев. Цель — с нуля дойти до уровня, с которым можно прийти на собеседование на стажёра QA Automation: понимать, как тестируют программы, разбираться в устройстве веба и API, писать простой код на Python и первые автотесты.

Ориентир по времени: **около 4 месяцев при 15–20 часах в неделю**. Кто-то пройдёт быстрее, кто-то медленнее — это нормально. Важнее понимать, чем успеть.

После этой фазы будет собеседование на стажёра. Оно не «зубодробительное»: мы проверяем, что база есть, ты думаешь как тестировщик и умеешь учиться. Опыта работы никто не ждёт.

## Шаг −1. Открой этот файл как следует

Этот файл в формате **Markdown** (расширение `.md`). Это обычный текст с простой разметкой: `#` — заголовок, `**слово**` — жирный шрифт, `- пункт` — список, `[текст](ссылка)` — ссылка. Если сейчас ты видишь звёздочки и решётки — файл открыт как простой текст. Читать так можно, но удобнее открыть его в программе, которая показывает разметку. Варианты:

**Задание:** найди 5 минут на [шпаргалку по Markdown от GitHub](https://docs.github.com/ru/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax) и попробуй сам написать короткий файл `about-me.md`: заголовок, пара строк о себе, список из трёх целей на обучение и одна ссылка. Его же потом положишь в репозиторий.

## Как работать

**1. Заведи учебный репозиторий на GitHub в первую же неделю.** Всё, что делаешь (решённые задачи, скрипты, чек-листы, баг-репорты, тесты), коммить туда. К собеседованию это станет твоим портфолио.

**2. Раз в неделю отправляй короткий отчёт.** Три пункта, не больше:

```
Неделя N
1. Что изучил: ...
2. Что сделал: ... (ссылки на коммиты/файлы в репозитории)
3. Что непонятно / где застрял: ...
```

**3. Раз в 2–3 недели — короткая встреча (около 30 минут).** Покажешь репозиторий и устно ответишь на несколько вопросов для самопроверки из этого файла. Это не экзамен, а сверка: всё ли идёт по плану и всё ли понятно.

**4. Если застрял:**

1. 30–60 минут пробуешь разобраться сам: перечитай материал, поищи ошибку в поиске, загляни в документацию.
2. Спроси в сообществе (чаты ниже) или попроси AI-ассистента *объяснить* (не решить за тебя).
3. Если не помогло — задай вопрос с контекстом: что делал, что ожидал, что получил, что уже пробовал.

Умение самостоятельно разбираться — такой же важный навык, как знание Python. Его тоже проверяют.

**5. AI-ассистенты (ChatGPT, Claude и другие) — только как репетитор.** Можно: «объясни этот код», «почему тут ошибка», «придумай мне 5 задач на словари». Нельзя: просить написать решение целиком и копировать его. На собеседовании код придётся писать и объяснять самому.

**6. Учи английский параллельно, по 20–30 минут в день.** Почти вся документация к инструментам — на английском. Цель — читать её со словарём.

## Этап 0. Азы IT (2–3 недели)

**Зачем:** чтобы дальше не спотыкаться о «а где у меня этот файл» и «что такое терминал».

**Что изучить**

- Как устроен компьютер в общих чертах: процессор, память, диск, операционная система, процесс, файл, сеть.
- Терминал: навигация (`ls`, `cd`, `pwd`), работа с файлами (`cat`, `less`, `cp`, `mv`, `rm`), поиск (`grep`), пайпы (`|`), переменные окружения, `curl`. Если у тебя Windows — сразу установи **WSL2** (Linux внутри Windows) и учись в нём.

- Редактор кода: VS Code или PyCharm Community. Освой терминал внутри редактора и расширение для Python.
- Как устроена разработка: кто такие аналитик, разработчик, тестировщик, DevOps; что такое задача, спринт, релиз; окружения dev / stage / prod.

**Материалы**

- Книга Чарльза Петцольда «Код. Тайный язык информатики» — по главе в день, целиком не обязательно.

- [The Linux Command Line](https://linuxcommand.org/tlcl.php) — бесплатная книга, первые 10 глав.
- [Pro Git на русском](https://git-scm.com/book/ru/v2) — главы 1–3.
- [Learn Git Branching](https://learngitbranching.js.org/?locale=ru_RU) — интерактивный тренажёр по Git.

**Практика**

- Заведи GitHub, создай учебный репозиторий, настрой SSH-ключ, сделай первый pull request в свой же репозиторий.
- Через `curl` получи JSON с любого публичного API (например, `curl https://jsonplaceholder.typicode.com/users`) и найди в нём нужное поле через `grep`.
- Пройди Learn Git Branching до раздела про rebase.

**Вопросы для самопроверки**

## Этап 1. Теория тестирования (3–4 недели)

**Зачем:** чтобы знать, *что* проверять, а не только *как*. Техники из этого этапа потом напрямую превращаются в автотесты.

**Что изучить**

- Зачем нужно тестирование; 7 принципов тестирования; QA, QC и тестирование — в чём разница.
- Уровни: модульное (unit), интеграционное, системное, приёмочное. Пирамида тестирования.
- Виды: функциональное и нефункциональное (производительность, безопасность, удобство, совместимость); smoke, регрессия, повторное тестирование.
- Чёрный, белый и серый ящик.
- Техники тест-дизайна: классы эквивалентности, граничные значения, таблицы решений, диаграммы состояний и переходов, попарное тестирование, предугадывание ошибок, исследовательское тестирование.
- Артефакты: требования, чек-лист, тест-кейс, баг-репорт, тест-план. Жизненный цикл бага. Серьёзность (severity) и приоритет (priority).
- Тестирование в Agile: критерии приёмки в формате Given / When / Then.

**Материалы**

- Артём Русов, [«Тестирование ПО с нуля»](https://stepik.org/course/171826/promo) на Stepik — бесплатно, начни с него.
- Олег Малышев, [«Тестировщик с нуля»](https://www.youtube.com/playlist?list=PLUmVnyc8_rTi3KfMNX7TBiiHXzuruXlmM) — плейлист на YouTube.
- Алексей Маршал, [«Тестирование ПО»](https://www.youtube.com/playlist?list=PLZqgWWF4O-zg03RGSZ2GpHLE3BmO8bjKo) — плейлист на YouTube; смотри темы, которые не зашли в первом курсе.
- Святослав Куликов, «Тестирование программного обеспечения. Базовый курс» (3-е изд.) — бесплатный PDF на сайте автора. Главы про автоматизацию в конце пока пропусти.
- [Силлабус ISTQB Foundation Level v4.0](https://istqb.org/certifications/certified-tester-foundation-level) — международный стандарт терминов (есть перевод на русский у RSTQB). Сдавать экзамен не нужно, используй как справочник.

**Практика**

- Возьми любую форму регистрации на публичном сайте и напиши к ней чек-лист. Отметь, где применил классы эквивалентности, а где — граничные значения.
- Найди и оформи 5 баг-репортов на учебных сайтах из раздела «Песочницы» в конце файла.

**Вопросы для самопроверки**

1. Чем smoke-тестирование отличается от регрессионного?
2. Поле принимает возраст от 18 до 60. Какие значения ты проверишь и почему?
3. Что должно быть в хорошем баг-репорте?
4. Чем severity отличается от priority? Приведи пример бага с высоким severity и низким priority.
5. Что такое пирамида тестирования и почему тестов через интерфейс должно быть меньше всего?
6. Чем тест-кейс отличается от чек-листа?

## Этап 2. Как устроен веб и API (2 недели)

**Зачем:** автотесты, которые ты будешь писать, — это в основном запросы к API. Здесь ты научишься делать их руками, без кода.

**Что изучить**

- Клиент и сервер, фронтенд и бэкенд, что такое API.
- Сеть на уровне понимания: IP, DNS, порт, HTTPS. Что происходит, когда вводишь адрес сайта.
- HTTP: методы (GET, POST, PUT, PATCH, DELETE), статус-коды (2xx, 3xx, 4xx, 5xx), заголовки, тело запроса, query-параметры, cookies.
- Формат JSON — уверенно читать и писать.
- Авторизация: логин и пароль, API-ключ, токен, что такое JWT.
- REST и документация API в Swagger / OpenAPI.
- Инструменты разработчика в браузере (DevTools): вкладки Network и Console.

**Материалы**

- [MDN: обзор протокола HTTP](https://developer.mozilla.org/ru/docs/Web/HTTP/Overview) и соседние статьи MDN про методы и статус-коды.
- [Видео Ulbi TV про REST, SOAP, GraphQL и WebSockets](https://www.youtube.com/watch?v=XaTwnKLQi4A).
- [Плейлист «Postman для тестировщика»](https://youtube.com/playlist?list=PLKbJd47KcbjvLgn-ukTvfpaGoXAqybza0).
- [jwt.io](https://jwt.io) — вставь любой токен и посмотри, из чего он состоит.

**Инструменты:** Postman или Bruno — для запросов к API; `curl` — то же самое из терминала. Привыкай повторять в `curl` любой запрос, который сделал в Postman.

**Практика**

- В [Swagger Petstore](https://petstore.swagger.io) или [Restful Booker](https://restful-booker.herokuapp.com) пройди полный сценарий: создать, получить, изменить, удалить запись. Сохрани коллекцию запросов в репозиторий.
- Напиши чек-лист проверок для одного эндпоинта: позитивные, негативные, граничные значения, неверные типы данных, запрос без токена.
- Открой любой знакомый сайт (маркетплейс, почту) с DevTools, найди 3 запроса к серверу и объясни, что делает каждый.

**Вопросы для самопроверки**

1. Чем GET отличается от POST? А PUT от PATCH?
2. Что означают статус-коды 200, 201, 400, 401, 403, 404, 500?
3. Чем 401 отличается от 403?
4. Что такое заголовки запроса? Назови 2–3 примера.
5. Что такое Swagger и как по нему понять, какой запрос отправить?

## Этап 3. Python (6–8 недель)

**Зачем:** на Python ты будешь писать автотесты. Это самый длинный этап — не торопись, решай много задач.

**Что изучить (по порядку)**

1. Переменные, типы данных (числа, строки, логический тип, `None`), ввод и вывод, условия, циклы.
2. Коллекции: список (list), словарь (dict), множество (set), кортеж (tuple). Особенно — вложенные словари и списки: это то же самое, что JSON.
3. Функции, аргументы.
4. Ошибки и исключения: `try / except`, как читать traceback (сообщение об ошибке).
5. Модули и импорты.
6. Работа с файлами и JSON.
7. Классы и объекты (основы ООП).
8. Аннотации типов (type hints) — на уровне «понимаю и использую».

**Окружение**

- Актуальная версия Python (3.13 или новее).
- [uv](https://docs.astral.sh/uv/) — для виртуальных окружений и установки библиотек.
- [Ruff](https://docs.astral.sh/ruff/) — проверка и форматирование кода.
- Научись пользоваться отладчиком в редакторе: точки остановки, пошаговое выполнение.

**Материалы**

- [«Поколение Python»: курс для начинающих](https://stepik.org/course/58852/promo) на Stepik — бесплатно, основной курс этапа.
- [«Поколение Python»: курс для продвинутых](https://stepik.org/68343) — продолжение, тоже бесплатно; можно выборочно.
- Эрик Мэтиз, «Изучаем Python» (3-е изд.) — первая часть как учебник.
- [Официальный Python Tutorial](https://docs.python.org/3/tutorial/) — как справочник.

**Практика**

- Реши не меньше 150 задач на Stepik. Самые интересные решения коммить в репозиторий.
- Задачи на [Codewars](https://www.codewars.com) уровней 8–6 kyu по 20 минут в день.
- Мини-проект: скрипт, который делает запрос к публичному API через библиотеку `requests`, сохраняет ответ в JSON-файл и проверяет, что в нём есть нужные поля. Это твой первый «автотест» без фреймворка.

**Вопросы для самопроверки**

1. Чем список отличается от словаря? Когда что использовать?
2. Как достать значение из словаря внутри списка внутри словаря?
3. Что делает `try / except`? Зачем ловить исключения?
4. Что такое класс и объект? Зачем они нужны?
5. Прочитай любой traceback из своей практики и объясни, где и почему упал код.
6. Что такое виртуальное окружение и зачем оно?

## Этап 4. SQL и базы данных (2 недели, параллельно с Python)

**Зачем:** автотесты часто проверяют не только ответ API, но и то, что в базе данных действительно появилась нужная запись.

**Что изучить**

- Таблицы, строки, столбцы, первичный и внешний ключи, связи между таблицами.
- `SELECT`, `WHERE`, `ORDER BY`, `LIMIT`, агрегатные функции, `GROUP BY`, `HAVING`, `JOIN`.
- `INSERT`, `UPDATE`, `DELETE`, что такое транзакция.
- PostgreSQL как основная база данных.

**Материалы**

- «Интерактивный тренажёр по SQL» на Stepik — бесплатно.
- [SQL Academy](https://sql-academy.org) — тренажёр на русском.

- [Плейлист «Основы SQL»](https://www.youtube.com/playlist?list=PLtPJ9lKvJ4oh5SdmGVusIVDPcELrJ2bsT).
- Программа для работы с базами: DBeaver.

**Практика**

- Установи PostgreSQL, загрузи учебную базу (например, демо-базу авиаперевозок от Postgres Pro) и напиши 20 запросов на «бизнес-вопросы»: сколько рейсов, какие самые загруженные аэропорты и т. д.
- Подключись к своей базе из Python (библиотека `psycopg`) и проверь результат запроса в коде.

**Вопросы для самопроверки**

1. Чем `WHERE` отличается от `HAVING`?
2. Что делает `JOIN`? Чем `INNER JOIN` отличается от `LEFT JOIN`?
3. Напиши запрос: все заказы пользователя с именем «Иван».
4. Что такое транзакция и зачем нужен `ROLLBACK`?

## Финал. Первые автотесты и входное задание (2–3 недели)

### Первые автотесты на pytest

**Что изучить**

- Что такое pytest; тест как функция; `assert`; запуск тестов и чтение падений.
- Простые фикстуры (подготовка данных до теста).
- `@pytest.mark.parametrize` — один тест с разными наборами данных. Именно сюда ложатся классы эквивалентности и граничные значения из этапа 1.
- Отправка запросов из теста через HTTPX (или Requests), проверка статус-кода и полей ответа.

**Материалы**

- [pytest — Get Started](https://docs.pytest.org/en/stable/getting-started.html).
- Брайан Оккен, «Python Testing with pytest» (2-е изд.) — первые 3 главы.
- Статья [«API автотесты на Python с запуском на CI/CD и Allure отчетом»](https://vc.ru/dev/2016474-api-avtotesty-na-python-s-cicd-i-otchetom-allure) — первая половина; остальное пригодится позже.

### Входное задание

Сделай в своём публичном репозитории:

1. **15–20 API-тестов на [Restful Booker](https://restful-booker.herokuapp.com)** на pytest: позитивные, негативные и параметризованные. Тесты не должны зависеть друг от друга и от порядка запуска.
2. **Чек-лист проверок для двух эндпоинтов** — с указанием, какие техники тест-дизайна ты применил.
3. **3 баг-репорта** на проблемы, которые найдёшь (в Restful Booker есть специально заложенные ошибки).
4. **README**: что это за проект и как его установить и запустить.
5. *Бонус:* автоматический запуск тестов в GitHub Actions.

Делай задание сам. На собеседовании тебя попросят провести по коду и объяснить, почему сделано именно так.

## Как пройдёт собеседование

Около часа, в спокойном формате. Примерно так:

1. Знакомство: почему тестирование, как учился, что было сложнее всего.
2. Разбор входного задания: проведёшь по репозиторию и расскажешь о своих решениях.
3. Вопросы по теории тестирования, HTTP и API — как в разделах «Вопросы для самопроверки».
4. Небольшая задача на Python и один SQL-запрос — вживую, без AI.
5. Твои вопросы к нам.

Если чего-то не знаешь — так и скажи и предложи, как бы ты это выяснил. Это нормальный и хороший ответ для стажёра.
